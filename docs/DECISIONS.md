# Technical decisions and trade-offs

| id | decision | why | trade-off / consequence |
|---|---|---|---|
| D-01 | Model the problem as **query-conditioned opinion retrieval**, not collaborative filtering | The hard part is finding the few opinions that answer *this* question ("lit streets, empty after midnight") before any LLM sees them. CF needs dense user-item interaction data we do not have and would rank by taste similarity, not by what an opinion says. | No CF is implemented or claimed. Social context enters only as an explicit, gated, evaluable ranking signal. |
| D-02 | **Prisma for schema/CRUD, raw SQL (`$queryRaw`) for FTS and pgvector** | Prisma cannot express tsvector/GIN/vector queries; bound parameters keep raw SQL injection-safe. | Two data-access styles; the tsvector and vector columns are `Unsupported(...)` in the schema. |
| D-03 | **Hand-written migration SQL**; plus `scripts/apply-migrations.ts` fallback | The generated tsvector column, GIN index, pgvector extension and CHECK constraints are outside what Prisma generates. The Prisma schema engine binary could not be downloaded in the build sandbox (`binaries.prisma.sh` blocked), so `prisma migrate deploy` could not be exercised there. | Schema and SQL can drift; mitigated by integration tests that exercise every model through Prisma Client. `npm run db:migrate` (standard) is **unverified here**; `npm run db:migrate:sql` is verified. Do not mix the two on one database. |
| D-04 | Embeddings in a separate table, **unconstrained `vector` column keyed by `(opinion_id, model)`**, exact cosine scan | Query and corpus vectors can never mix models or dimensions (always `WHERE model = …`); providers with different dimensions coexist. | No ANN index by default (unconstrained dimension); fine at this scale. For large corpora create a per-model expression HNSW index (documented in LIMITATIONS). |
| D-05 | **Inner circle is configurable**: ACCEPTED + type ∈ `INNER_CIRCLE_TYPES` (default FRIEND,FAMILY) + closeness ≥ `INNER_CIRCLE_MIN_CLOSENESS` (default 4) | Accepted connection ≠ close friend. PENDING and BLOCKED grant nothing; BLOCKED also hides the user's public opinions. | One symmetric closeness value per relationship (no per-direction trust). |
| D-06 | **Authorization inside every SQL query**, re-asserted in TypeScript before ranking, logging and LLM prompts | Unauthorized rows never leave the database; a bug in either layer is caught by the other and by tests (incl. an SQL≡TS equivalence test and mutation checks). | Slightly more complex SQL building. |
| D-07 | Search-run logs store **ids, scores, metadata – never opinion text** | Logs and debug endpoints cannot leak private content; runs are owner-only (404 for others). | Reading a past run's text requires re-querying with current permissions. |
| D-08 | Polarity/contradiction is an **evidence characteristic, not a ranking signal** | Negative and contradictory evidence must be preserved (spec). Penalising it would hide the very reports a cautious traveller needs. | Query-side polarity ("not good for…", "cheap", "dark") is not matched → known failure cases (EVALUATION §3). |
| D-09 | Three **genuinely distinct** modes; hybrid = union by id + completion queries + reranker | Lexical = FTS only; semantic = vectors only; hybrid adds aspect/context/etc. | Hybrid's gain mixes "both signals" with "extra heuristic signals" (the ablations separate them). |
| D-10 | **No silent fallback**: semantic/hybrid without vectors → `503 SEMANTIC_RETRIEVAL_UNAVAILABLE`; `allowFallback=true` returns a labelled lexical result (`retrieval.fallback`, `FALLBACK` warning) | The caller must always know which method produced the results. | One extra flag for clients. |
| D-11 | **Local embedding provider = averaged GloVe (SIF-weighted)**, optional OpenAI-compatible provider, test-only hash provider | No hosted model was reachable from the build sandbox, but "actual embeddings" were required and evaluation had to run offline. GloVe is a real learned embedding (public GitHub-hosted release, PDDL). | Static, non-contextual: weaker than modern sentence encoders. The test-only hash provider is blocked outside tests and its metrics are never reported as semantic. |
| D-12 | **Rule-based aspect lexicon** (`lexicon-v1`) stored separately from text | Offline, transparent, deterministic aspect signal and polarity for display. | A concept heuristic, not semantic understanding; coverage limited to ~20 hand-written aspects. |
| D-13 | ~~Demo authentication via `x-user-id`~~ **Superseded by D-18** | It let the retrieval/authorization logic be built and tested first. | Removed: the header no longer authenticates anything (tested). |
| D-14 | Replaceable provider interfaces (embeddings, LLM, web); **all optional** | The lexical baseline, evaluation and tests run with no keys. Providers fail soft with disclosed warnings; invalid LLM JSON or fabricated citation ids are discarded. | Live provider code is only mock-tested here. |
| D-15 | Node 22 / TS / Fastify 5 / Prisma 7.10 (`@prisma/adapter-pg`) / Zod 4 / Vitest 5, versions pinned by `package-lock.json` | Maintained majors verified with `npm ls` at build time. Prisma 7 uses the driver-adapter client and `prisma.config.ts`. | ESLint not configured (type-check is the static gate). |
| D-16 | Thresholds tuned on a **dev split only**, reported on test | Avoids tuning on the reported numbers. | 33 queries: weak protocol, honest about it. |
| D-17 | LLM output is *validated and grounded*, never trusted | Intent: schema-checked, city/firsthand/time claims must literally appear in the query; unknown aspect ids demoted to soft preferences. Answers: only selected authorized evidence is sent (no author identities); any cited id outside it discards the answer. | More conservative than raw LLM output. |
| D-18 | **Real authentication: email + password, scrypt, opaque server-side sessions** | Replaces the demo header. scrypt ships in Node (no native build), is memory-hard, and its parameters are stored in the hash so the cost can be raised and old hashes upgraded on login. Server-side sessions revoke instantly (logout, password change, disable) and store only SHA-256(token). | One DB lookup per request; no SSO/OAuth; no email verification, reset or MFA (docs/AUTH.md §8). |
| D-19 | **HttpOnly SameSite=Lax cookie for browsers + Bearer tokens for API clients; Origin/Sec-Fetch-Site CSRF check; strict CSP** | Script cannot read the cookie, so XSS cannot steal sessions; cross-site writes are rejected; bearer tokens are not ambient credentials so they skip the CSRF check. | The CSRF defence assumes modern browsers. A bug found by tests: `new URL("http://h:80").host` drops the default port, so the origin comparison normalises both sides with the Origin's scheme. |
| D-20 | **Login hardening**: identical error for unknown email / wrong password / disabled; dummy hash for timing; per-(email,IP) lockout; IP limit | Prevents account enumeration by response and by timing, and slows guessing. | Limits are per process (in memory). Registration still reveals existing emails (409) because there is no email channel. |
| D-21 | **The inner circle is user-managed** (requests, accept, type, closeness, block) with the same rule as before | Gives the rule a real data source instead of seeded rows; users can see and edit exactly what makes someone "inner circle". | One shared closeness number per tie; people can only be found if they have an account. |
| D-22 | **Datasets are imported by the user, never bundled; licence acknowledgement is mandatory** (`--accept-license`) | The only realistic location-aware review datasets are non-commercial, restricted or non-redistributable; the build environment could not even reach them. | The user must download data and the first real import is unverified here (fixtures only). |
| D-23 | **`data_sources` table with governance flags** (`commercialUseAllowed`, `publicDisplayAllowed`) enforced in the SQL authorization predicate | A "do not republish" source can be stored for private analysis but is hidden from other users in production by default. | Policy is deployment-wide, not per user. |
| D-24 | **Pseudonymous authors with a per-import random HMAC key**; reviewer names never read; masking of emails/links/phones/handles | Imported reviewers are real people; irreversible pseudonyms keep "distinct authors" meaningful without storing identities. | Names in free text remain; re-importing yields new pseudonyms (so imports replace, not merge, by default). |
| D-25 | **Imports validate before they destroy** (pre-flight on the first row) and are idempotent per source | A test found that a wrong file used to wipe earlier data. | A crash mid-import leaves a partial source; re-running replaces it. |
| D-26 | **The benchmark is pinned to the synthetic corpus** (`filters.dataSources=["synthetic-seed-v1"]`) | Imported/user rows have no judgments and would be counted as irrelevant, silently distorting every metric. | There is no accuracy measurement on real data. A test and a full re-run confirmed identical metrics with imports present. |
| D-27 | **An empty JSON body is `{}`** | Action endpoints (`/accept`, `/decline`) can be POSTed without a payload; malformed JSON is still 400. | — |
